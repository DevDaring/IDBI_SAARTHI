§ Where you stand

Is a real model working today? Yes — but nothing is trained in advance

The hosted app trains a genuine LightGBM with isotonic calibration from scratch on every upload (verified: AUC 0.97 on real SBA data, leakage-free). That makes SAARTHI an excellent adaptive AutoML tool — but it ships no pre-trained model artifact. IDBI's brief asks for a trained model for default prediction. A judge who uploads a tiny or unlabeled file today sees the system's weakest behaviour, not its best.

Known gaps to close (from code review)
  • No persisted model — nothing survives a restart; every demo is a cold start.
  • Calibration metrics are optimistic — ECE/Brier are computed on the same fold the isotonic calibrator is fit on; ~75% of displayed PDs are in-sample. Needs a third split.
  • TabPFN path never fires — the library was never installed, yet the UI says "Trying TabPFN foundation model".
  • Transaction & social features don't exist yet — the feature builder is tabular one-hot only; "text purpose" is a 24-keyword count.
Strategy in one sentence

Convert SAARTHI from "trains on whatever you upload" into "arrives pre-trained on 3.5M public loans and 25M transactions, then fine-tunes on your book in minutes" — which is strictly stronger than either a static model or an AutoML tool, and matches the brief exactly.

§ The model

Three pillars and a stacker

Every serious benchmark and both landmark Kaggle credit competitions agree on the same shape: gradient boosting remains the backbone for tabular credit risk, sequence models add real lift when transaction history exists, and foundation models win on small data. So don't pick one — build the ensemble the evidence prescribes, and keep SAARTHI's judge-verified explainability layer on top (no competitor will have it).

PILLAR A · GBDT CORELightGBM + XGBoost + CatBoost, 5-fold bagged, trained on the pooled canonical corpus.
The proven winner: Amex & Home Credit top solutions are all GBDT-centred. Ships as saarthi_global.pkl.
PILLAR B · TXN-AS-LANGUAGECoLES contrastive encoder (pytorch-lifestream) pretrained on TabFormer 24M + Berka 1M + Amex sequences → 256-d borrower embedding.
Sberbank's production-proven recipe (SIGMOD '22); TabBERT is the stretch goal.
PILLAR C · FOUNDATION MODELTabPFN v2 (Nature 2025) as ensemble member for portfolios ≤10K rows — where hackathon demo uploads actually live.
Install it for real this time. Use v2 (permissive license), not 2.5 (research-only).

META-LAYERLogistic stacker → isotonic calibration on an untouched third split → discrete-time hazard head for the 12-month curve → SHAP + faithfulness-judge explanation layer (unchanged — your moat).

How this lands in the existing codebase

  • Fix the split first — model.py goes from 2-way to 3-way (fit / calibrate / test); metrics move to the untouched fold. Half a day, and it makes every number you publish defensible.
  • Global model at startup — the Flask app loads saarthi_global.pkl; an upload without labels gets scored instantly (new capability!), an upload with labels gets the current fine-tune path plus the global score as a stacked feature.
  • Transaction ingestion — new canonical entity: a transactions file (date, amount, dr/cr, narration, balance) keyed by loan-id, exactly the shape of IDBI API 393's response. The CoLES encoder turns each borrower's sequence into an embedding appended to the feature matrix.
  • Survival upgrade — where panel data exists (Berka, Amex, Taiwan), fit a discrete-time logistic hazard model instead of the Weibull heuristic; keep the "estimated" label honest where it doesn't.

§ Suiting IDBI without IDBI's data

The GST simulation layer — your unfair advantage

You already hold IDBI's exact schemas: the Data Field Requirements PDF (GST behavioural fields) and the 25-API catalogue with full request/response JSON. Nobody needs the sandbox to demonstrate readiness for it.

  • GST feature simulator — upgrade make_sample_data.py into a generator that emits every field in their GST response (filing delays, turnover growth, ITC mismatch, customer concentration…), with default propensity calibrated to published RBI Financial Stability Report MSME GNPA levels. Train the model with these features present, so the moment real GST data appears, the pipeline already speaks it.
  • Mock IDBI APIs — a tiny local service that serves synthetic borrowers in the byte-exact shapes of API 391 (loan master), 402 (overdue/NPA), 393 (statement with narration). The demo then shows SAARTHI consuming IDBI's own interfaces live — a plug-in-ready story with zero NDA exposure.
  • Social/digital signals — keep as a roadmap slide plus synthetic fields (presence flag, review rating, posting recency) in the simulator. Without consented real data this must stay demo-tier; presenting it as governed-by-consent shows maturity, not weakness.
Why this wins

Every other team either signed the NDA (and is now stuck integrating in a locked sandbox) or trained a generic Kaggle model. You show up with a pre-trained model, published-benchmark numbers, and a live demo speaking IDBI's own API dialect — plus a verified-explanation layer nobody else has.

§ Proof

Evaluation protocol that survives judges and reviewers

  • Leave-one-dataset-out — train the global model on all-but-one corpus, test on the held-out one. This is the honest measure of "will it transfer to IDBI's book," and it's the headline table for both deck and paper.
  • Temporal stability — Lending Club by vintage (≤2015 → 2016–18) and the Home Credit 2024 stability metric. Banks fear score drift more than they love AUC.
  • Calibration done right — ECE/Brier only on the untouched test fold, with reliability diagrams. Today's near-zero ECE is an artifact of fitting and scoring isotonic on the same fold; fixing it turns a paper-killer into a talking point.
  • Published baselines to beat — SBA ≈ 0.95+ AUC (literature), Taiwan ≈ 0.78, Home Credit winner 0.805, Amex metric 0.80. Land within a point of these and you're provably state-of-competition, not just "high AUC on my own CSV."
  • Ablation ladder — GBDT alone → +txn embeddings → +TabPFN → +stacker. One chart that justifies every architectural choice and doubles as the paper's core figure.
